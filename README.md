# سامانه آموزش و ارزیابی کار و فناوری

پروژه به دو اپ جدا تقسیم شده — هرکدوم می‌تونن مستقل دیپلوی و به اپ اندروید تبدیل بشن.

## ساختار فایل‌ها

```
index.html          ← صفحه‌ی ورودی: انتخاب دانش‌آموز یا مربی
shared/              ← فایل‌های مشترک بین هر دو اپ
  css/style.css
  js/config.js        ← تنظیمات Supabase (SUPABASE_URL / SUPABASE_ANON_KEY)
  js/state.js          ← وضعیت مشترک برنامه
  js/utils.js           ← توابع کمکی عمومی
  js/vendor/supabase.js  ← کتابخانه‌ی Supabase
student/             ← اپ دانش‌آموز (مستقل، قابل تبدیل به اپ اندروید جدا)
  index.html
  manifest.json، sw.js، آیکون‌ها
  js/auth.js، student.js، games.js، main.js
teacher/             ← اپ مربی/ادمین (مستقل، قابل تبدیل به اپ اندروید جدا)
  index.html
  manifest.json، sw.js، آیکون‌ها
  js/auth.js، teacher.js، district.js، main.js
karvfan-android/     ← پروژه‌ی اندروید (Capacitor) — در حال حاضر مشترک، به‌زودی جدا می‌شه
```

## دیپلوی

این ریپو به Cloudflare Workers (Static Assets) وصل شده — هر پوش روی برنچ `main`
به‌صورت خودکار دیپلوی می‌شه (از طریق تنظیمات Build در داشبورد Cloudflare، دستور
`npx wrangler deploy`).

## بک‌اند

هر دو اپ به یک پروژه‌ی Supabase مشترک وصل می‌شن — یعنی داده‌ها (دانش‌آموزان، درس‌ها،
تکالیف و...) بین هر دو اپ به‌اشتراک گذاشته می‌شه.

## کیفیت کد و تست

- `npm run lint` — بررسی سبک و خطاهای رایج با ESLint
- `npm run format` — یکدست‌سازی فرمت با Prettier
- `npm test` — تست‌های واحد (Node.js built-in test runner) برای توابع خالص در `shared/js/utils.js`

## محدودیت‌های شناخته‌شده / نیازمند بررسی جداگانه

این‌ها نیاز به دسترسی به داشبورد Supabase (نه فقط کد این ریپو) دارن و در این دور از تغییرات اعمال نشدن:

- **طول پین دانش‌آموز**: در حال حاضر پین ۴ رقمیه. افزایش طول یا سخت‌گیرتر کردن قفل حساب نیاز به تغییر در تابع/RPC سمت دیتابیس (`student_login`, `student_login_or_register`) داره.
- **جواب بازی‌ها سمت کلاینت**: پاسخ‌های صحیح بازی‌های آموزشی (مثل «کارآگاه ایمیل») در `shared/js/config.js` و قابل مشاهده در کد کلاینته. برای بازی آموزشی مسئله‌ی مهمی نیست، ولی اگه صحت امتیازدهی مهمه باید منطق درست/غلط به یک Edge Function یا RPC منتقل بشه.
- **جدا کردن اپ اندروید**: طبق نقشه‌ی راه بالا هنوز `karvfan-android` مشترکه.
- **محیط جدا برای dev/staging**: در حال حاضر یک پروژه‌ی Supabase مشترک برای توسعه و تولید استفاده می‌شه.
