# ساختار جدید و حرفه‌ای پروژه‌ی Karvfan

از این پس، پروژه به‌جای یک فایل بزرگ، توی چند فایل مرتب سازمان‌دهی شده — نگه‌داری و ارتقاش خیلی راحت‌تره.

## ساختار فایل‌ها

```
index.html          ← اسکلت اصلی صفحه (فقط HTML)
css/
  style.css          ← تمام استایل‌ها و رنگ‌بندی
js/
  config.js           ← تنظیمات Supabase + ثابت‌ها + محتوای بازی‌ها
  state.js             ← وضعیت مشترک برنامه (اطلاعات دانش‌آموز فعلی و...)
  utils.js              ← توابع کمکی عمومی
  auth.js                ← ورود/ثبت‌نام دانش‌آموز و مربی
  student.js               ← کل تجربه‌ی دانش‌آموز
  games.js                  ← موتور بازی‌ها و آزمون‌ها
  teacher.js                 ← پنل مربی
  district.js                 ← آمار کلان و مدیریت کارکنان
  main.js                      ← نقطه‌ی شروع برنامه
manifest.json، sw.js، icon-*.png   ← فایل‌های قابلیت نصب (PWA)
```

## نحوه‌ی آپلود در گیت‌هاب (فقط یک‌بار)

چون الان چند فایل و پوشه داریم، ساده‌ترین راه:

1. زیپی که فرستادم رو دانلود و از حالت فشرده خارج کنید (Extract).
2. برید به صفحه‌ی اصلی ریپازیتوری `karvfan` توی github.com.
3. **همه‌ی فایل‌های قبلی رو پاک نکنید** — فقط از دکمه‌ی «Add file → Upload files» استفاده کنید.
4. کل محتوای پوشه‌ی استخراج‌شده (همه‌ی فایل‌ها و پوشه‌های `css` و `js`) رو با هم بکشید و داخل کادر آپلود گیت‌هاب رها کنید (Drag & Drop) — مرورگرهای امروزی ساختار پوشه‌ها رو حفظ می‌کنن.
5. پایین صفحه **Commit changes** رو بزنید.
6. Cloudflare طبق روال قبل، خودکار نسخه‌ی جدید رو دیپلوی می‌کنه.

## از این به بعد، وقتی فقط یه بخش عوض می‌شه

دیگه لازم نیست کل فایل رو جایگزین کنید — من دقیقاً می‌گم کدوم فایل(ها) عوض شده (مثلاً فقط `js/student.js`) و شما فقط همون فایل رو توی گیت‌هاب آپلود/جایگزین می‌کنید (روی فایل هم‌نام قبلی Overwrite می‌شه).

## چرا این‌جوری بهتره؟

- هر فایل مسئول یه بخش مشخصه — پیدا کردن و اصلاح چیزی خیلی سریع‌تره.
- بدون نیاز به هیچ ابزار build یا نصب چیزی — همون‌طور که تا الان کار می‌کرد، کار می‌کنه (فقط فایل‌های ساده‌ی HTML/CSS/JS).
- برای بزرگ‌شدن پروژه در آینده (مثلاً اضافه‌کردن درس دیگه، یا یه بخش کاملاً جدید)، فقط یه فایل جدید اضافه می‌شه، بدون دست‌زدن به بقیه.
